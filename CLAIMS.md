# Claims

Every public statement Porter makes on its site and in its README, with how to check it.

- **REPRODUCIBLE**: a command in this repository shows it. `pnpm test <file>` runs one test file; `pnpm eval …` and `pnpm shadow …` need an Otari org set up as in the [README](README.md#run-it-yourself).
- **VERIFIED-LIVE**: a URL on https://porter-frontdesk.vercel.app shows it. The last column says whether it can be seen there today, and links the run page that shows it. Porter's Otari balance is funded since 9 November 2026; [JUDGES.md](JUDGES.md#what-is-live) has the status of each part.
- **MODELED**: a number computed from a formula, not measured.
- **POST-HOC**: measured from a committed results file, in a run made after the pre-registered results were in that changed one thing; not pre-registered, and labelled so wherever it appears.
- **UNPUBLISHED**: seen in a run whose results file is not in this repository; stated as an approximation, and not checkable here.
- **NOT-CLAIMED**: listed at the end.

Runs from before about 17:00 UTC on 9 November (for example [run d1c674d7](https://porter-frontdesk.vercel.app/console/runs/d1c674d7-895d-4cf8-a89d-88acf41050cc) and [run 994e344a](https://porter-frontdesk.vercel.app/console/runs/994e344a-8441-4249-8ed4-b83467d3c00b)) predate cost recording and the fix that installs the repository in the sandbox; their pages can show a cost of $0 and a failed package install. They are cited only for what they show: tool calls, and the approval on [porter-demo#11](https://github.com/RaYYeR220/porter-demo/issues/11).

No measured number on the site or in the README is typed by hand; the numbers that are typed are configuration (budgets, limits and constants named in the code). Eval and spam-wave numbers come from `results/*.json` through `pnpm eval:render` and the page loaders; until those files are committed, every cell says "Not run yet". The short "What we measured" list at the top of the README and the measured line on the front page are computed from the same files, the read-only run over Otari's tracker included.

## Not claimed

- That the guard catches every prompt injection. The eval measures 25 attacks written for this bot, each run once; one hijack more or less is within noise.
- That Otari's gateway guardrails see model output. They are input-only; the output check on the reply is Porter's own code.
- That a triage call fetches at most two pages, or only the hosts its prompt names. Hosted Otari takes no fetch settings on the request; the hard limit is the workspace's web-fetch policy, and the prompt's limits are instructions.
- That an instruction inside a page fetched during the tool loop is detected. Porter claims containment for that case (read-only tools, link allowlist), not detection.
- That Porter's layers beat the prompt-only bot on hijacks with the production models. In the pre-registered run neither arm was hijacked; the difference showed in where attacks stopped, in cost, and with a smaller model (post-hoc).
- That a post-hoc run is pre-registered or replaces the pre-registered result. Each changed one thing after the results were in.
- That every legitimate issue is answered. Replies that quote the project's own host are held for a maintainer until a per-repository allowlist ships.
- Any hijack rate, false-block rate or cost figure that is not in `results/*.json`.
- That the spam wave's N=100 cost was measured. It is modeled, with the formula shown.
- That the guard's own model cost is inside the per-run or per-arm numbers. It bills to the `guard` workspace and is estimated, not measured.
- That a held issue is hostile. Legitimate security reports can read like an injection and be held for a maintainer; the eval's false-block count measures how often real issues are held.
- That a fallback happened in any particular run. A fallback shows only when a provider fails.
- That a shadow-report claim is correct unless a person checked it.
- Anything about reproducing snippets in languages other than Python.
- Anything about latency.
- That the public console is access-controlled. It is a demo: anyone can approve proposals (demo repository only) and change author tiers, rate-limited per IP and logged.
- That Porter fixes code or opens pull requests. It triages and proposes; a maintainer decides.
