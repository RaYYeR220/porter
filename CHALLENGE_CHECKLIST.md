# Requirements checklist

Each requirement on this checklist, and where to check it: in the code, on the live site, and in the Otari dashboard of the org running Porter. Pages are on https://porter-frontdesk.vercel.app. For what is live today, see [JUDGES.md](JUDGES.md#what-is-live).

## Repository

- Branch: `devs-wilding`.
- First commit where Otari came in: [`88418d5` Add Otari gateway client](https://github.com/RaYYeR220/porter/commit/88418d5ef15d8924f460dcff718e49bfcab4eb53) ([`lib/otari/client.ts`](lib/otari/client.ts), [`lib/otari/errors.ts`](lib/otari/errors.ts)).
- Everything runs on hosted otari.ai: `/api/v1` on the org's regional host, no self-hosted gateway.

## Open-weight models

| Requirement | Evidence |
| --- | --- |
| Uses open-weight models | Every model in the runtime path is open-weight: `deepseek/deepseek-v4.1-flash-1017`, `deepseek/deepseek-v4-flash-0731`, Qwen3 Coder 480B, GLM-5.3-Flash, `alibaba/qwen3guard-gen-8b`, `openai/gpt-oss-safeguard-120b`, `meta/llama-guard-4-12b`, `alibaba/qwen3-embedding-4b`, plus the fallbacks listed in the [README](README.md#open-weight-models-and-their-roles), among them `openai/gpt-oss-120b`. Code names routing policies, never a closed model id: [`lib/agent/roles.ts`](lib/agent/roles.ts), [`packages/porter-guard/src/protocol.ts`](packages/porter-guard/src/protocol.ts), [`lib/snapshot/embed.ts`](lib/snapshot/embed.ts). |
| Two or more open-weight models with different purposes | Triage (DeepSeek V4.1 Flash), tier-down (DeepSeek V4 Flash), repro (Qwen3 Coder), review (GLM-5.3-Flash), injection classifiers (Qwen3Guard, gpt-oss-safeguard), harm classifier (Llama Guard 4), duplicate search (Qwen3-Embedding). Site: each step of a run trace on /console shows the model that served it. Dashboard: Overview → Requests, one served model per request. |

## Otari features

| Feature | In the code | On the site | In the Otari dashboard |
| --- | --- | --- | --- |
| Model routing and fallbacks | Roles call policies `porter-triage` (tier down from 80 % of the author's budget, then a fallback chain), `porter-repro` and `porter-review` (fallback): [`lib/agent/roles.ts`](lib/agent/roles.ts). `Otari-Model`, `Otari-Provider`, `Otari-Fallback`, `Otari-Attempt-Count` are recorded per step: [`lib/otari/client.ts`](lib/otari/client.ts), [`lib/agent/pipeline.ts`](lib/agent/pipeline.ts). | Run trace: "policy → served model, provider", fallback badge with the attempt count, the tier-down model on a near-cap author. | Workspace → Routing (the three policies). Overview → Requests: routing plan, attempted models, skipped candidates. |
| MCP integrations | Porter's MCP server: [`app/api/mcp/[transport]/route.ts`](app/api/mcp/%5Btransport%5D/route.ts), [`lib/mcp/tools.ts`](lib/mcp/tools.ts). Stored server passed as `mcp_server_ids` so the gateway runs the tool loop: [`lib/agent/triage.ts`](lib/agent/triage.ts). Approvals through caller-orchestrated `GET /mcp/servers/{id}/tools` and `POST /mcp/execute` on the maintainer key: [`lib/github/commands.ts`](lib/github/commands.ts). | MCP tool calls in the triage step of a trace. Approve on /console turns a proposal executed. | Workspace `desk` → Tools → MCP servers → `porter-repo`: the Connection card, Read tools, and the ACL rules (`desk-strangers` Read tools only, `desk-maintainer` Any, default Deny). Overview → Sessions: MCP spans under `run-<id>`. |
| Web search or web fetch | `otari_web_fetch` on the triage call, declared with no settings because hosted Otari refuses per-request fetch settings: [`lib/agent/triage.ts`](lib/agent/triage.ts). The allowed hosts are the workspace's web-fetch policy; the prompt names them and asks for at most two pages. Web search is not used. | Fetch calls, with their URL, in the triage step of a trace. | Workspace `desk` → Tools: "Allow in desk" under `otari_web_fetch` (one toggle for fetch and search), Advanced → Allowed domains. Overview → Sessions: fetch spans. |
| Code execution | `otari_code_execution` on the repro call; a run is proven only by an `otari_tool_calls` entry of type `code_execution` with an exit code: [`lib/agent/repro.ts`](lib/agent/repro.ts). | /try **Python bug** preset: the repro step's "ran in the sandbox · exit N" chip with code, stdout and stderr. | Overview → Sessions: sandbox spans. |
| Budgets and spending limits | Workspace ceilings on `desk`, `guard`, `baseline`; key budgets on `desk-maintainer`, `ops`, `guard`. `GET /key/budget` gates /try: [`lib/balance.ts`](lib/balance.ts). 402 handling: [`lib/agent/pipeline.ts`](lib/agent/pipeline.ts). Explicit `max_tokens` per role: [`lib/agent/roles.ts`](lib/agent/roles.ts). | /try: "Paused while the balance is low" when the strangers key nears its limits. Each trace step's cost. | Organization → Spend & budgets: budgets and ceilings. Workspace → API keys: each key's budget. |
| Multiple models serving distinct roles | Seven distinct jobs across eight models (table above): [`lib/agent/roles.ts`](lib/agent/roles.ts), [`packages/porter-guard/src/classifiers.ts`](packages/porter-guard/src/classifiers.ts), [`lib/snapshot/embed.ts`](lib/snapshot/embed.ts). Every call tags its role: `Otari-Tags: app=porter,role=<role>`. | Run trace: one step per role, each with its served model. | Overview → Requests and Sessions: one issue's triage, repro and review calls, each on its own model. |
| Guardrails | Porter's guard service, base URL `https://<host>/api/guard` (Otari posts to its `/validate`), is an org-level guardrail, mandated on workspace `desk`, mode `block`: [`app/api/guard/validate/route.ts`](app/api/guard/validate/route.ts), [`packages/porter-guard/`](packages/porter-guard/README.md) (profiles `prompt-injection`, `secrets`, `harm`). The 403 `guardrail_violation` becomes a held run with a fixed reply: [`lib/otari/errors.ts`](lib/otari/errors.ts), [`lib/agent/pipeline.ts`](lib/agent/pipeline.ts). | Live: a direct chat request through the desk stranger key, with an issue-shaped message containing a hidden comment addressed to the bot, was refused with 403 `guardrail_violation` and porter-guard's explanation before any model was called ([JUDGES.md](JUDGES.md#what-is-live)). /try **Hidden instruction** preset: sends the same kind of text through the same key, so it is expected to be held at triage with 0 answer tokens and the profile and explanation on the step. /eval: how many attacks stopped at the gateway. | Organization → Guardrails: three "Your own guardrails service" mandates (`prompt-injection`, `secrets`, `harm`) running in `desk`. Overview → Sessions: guardrail spans. |
| Per-user budgets | Service key `desk-strangers` with end-user budgets `newcomer` (default) and `regular`; `user` = `gh:<login>` or `web:<hash>` on every stranger call: [`lib/agent/triage.ts`](lib/agent/triage.ts). `GET /end-users`, `PUT`/`PATCH /end-users` for meters, upgrade and block: [`lib/authors.ts`](lib/authors.ts). Fixed refusal with `Retry-After`: [`lib/agent/replies.ts`](lib/agent/replies.ts). | /console Authors: per-author meters. /try **Spam wave**: one visitor's allowance drains, then the gateway refuses. /eval: the spam wave against a second author. | Workspace → API keys → `desk-strangers`: service key with its end-user budgets. Organization → Spend & budgets: `newcomer`, `regular`. |
